# LLM Wiki 导入批次清单

> 版本 v0.1 ｜ 更新：2026-09-09 ｜ 配套目录：`data/import_batches/`
> 用途：把 64 份清洗后语料按「业务主题 + 价值」切成 5 批，逐批导入 LLM Wiki，规避免费模型速率限制、逐批验收质量。

---

## 0. 一句话结论

**不用为「上下文 200k」担心**——LLM Wiki 是逐份/分块处理，不是把 64 份一次性塞进上下文。真正要盯的是**速率限制（免费版并发低）**和**抽取质量**，所以用「分批导入 + 先试点」来应对。

- 语料总量：64 份 / 753KB / **约 23.7 万字符**
- 最大单文件：聊天记录 3.7 万字符（≈4~5 万 token，远低于 200k）
- 模型用 **glm-4.6**（付费但便宜、质量稳、实测通过；免费 flash 模型限流严格，见下方实测结论）

## 3. 操作步骤（在 LLM Wiki GUI 里）

1. 设置 → 配好智谱 API（`glm-4.6`）。
2. 项目 → 资料源 Sources → 导入文件夹，选 **batch1 目录**（完整路径 `data/import_batches/batch1_核心_会议纪要智能纪要`）。
3. 观察活动面板，等 batch1 编译完 → 聊天提问验收。
4. 验收通过后，按 batch2 → batch3 → batch4 顺序逐批导入。
5. batch5 视需要导入（可跳过「提出企业ai化建议」）。

## 4. 模型实测结论（2026-09-09 已实测）

| 模型 | 实测结果 |
|---|---|
| `glm-4.6` | ✅ 正常（主力推荐，付费但便宜） |
| `glm-4-flash` | ✅ 可用（轻量，质量一般） |
| `glm-5.3-flash` | ✅ 可用（轻量） |
| `glm-4.7-flash` | ⚠️ 触发**速率限制**（code 1302，免费账号并发≈1，串行导入会频繁报错） |

> 结论：**用 `glm-4.6`**，别用免费 flash——导入 64 份文档要连续大量调用，免费限流会卡死。编译成本（约 23.7 万字符 × 两步思维链 ≈ 几十万 token）用 glm-4.6 也就几块钱，值。

| 风险 | 应对 |
|---|---|
| 免费模型限流（实测 1302） | 已弃用免费模型，改 glm-4.6 |
| 抽取质量 | 先导 batch1 试点，看 wiki 页面结构是否合理 |
| 单批过大导致一次请求超限 | 每批最大 7.4 万字符，远低于 200k，无此风险 |
