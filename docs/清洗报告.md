# 清洗报告（阶段 1）

> 产出日期：2026-09-09
> 脚本：`scripts/clean_text.py`（纯文字）、`scripts/extract_docx.py`（docx 抽文字），均可复用、可复现

## 一、处理范围

- **源目录**：`工作内容/`（只读，未改动任何原始文件）
- **输出目录**：`data/clean/`（保留目录结构）
- **处理对象**：纯文字（txt + md）40 个 + docx 抽文字 24 个（含 13 份 DLS 培训手册）= **64 个清洗后文件**
- **未处理**：pdf（20）、xlsx（11）、png/jpg（67）——图片 OCR 与客户订单 PDF 延后

## 二、脱敏规则

### 人名映射（保留「导师 / 学员」角色结构）

| 类别 | 原名 → 化名 |
|---|---|
| 导师/讲师 | 5 位导师（导师A~E），真实姓名见本地 `maps_local.py`（不入库） |
| 学员 | 6 位学员（学员A~F），真实姓名见本地 `maps_local.py`（不入库） |

### 公司与客户泛化

| 类别 | 原名 → 泛化 |
|---|---|
| 公司 | 某外贸公司（真实公司名见 `maps_local.py`） |
| 工厂 | 内地工厂 / 海外工厂（真实工厂名见 `maps_local.py`） |
| 客户 | 客户A / 客户B（真实客户名见 `maps_local.py`） |

### 其他规则

| 规则 | 处理 |
|---|---|
| 带客户前缀订单号 | → `[订单号]` |
| URL（飞书链接等） | → `[链接]` |
| 内网 IP | → `[内网地址]` |

## 四、元数据规范

每个清洗后文件头部统一标注：

```text
# ---- 元数据 ----
# 来源目录: <相对路径>
# 业务主题: <培训会议纪要 / 群聊答疑 / 单据理解 / DLS系统操作手册 / …>
# 原文件名: <文件名>
# 已脱敏: 是
# ---- 正文 ----
```

业务主题按来源目录自动归类：培训会议纪要、群聊答疑记录、学员学习笔记、单据理解、DLS系统操作手册、订单理单实操、项目背景方案、项目规划。

## 五、待办与遗留（下一步）

1. **图片 OCR**：67 张 PDF 截图，成本高、质量不确定，延后
2. **纯数字订单号人工核对**：如「873357」「53885497」这类无前缀纯数字，为避免误伤日期/金额，脚本未自动替换，需人工确认
3. **客户原始订单 PDF**（英文订单）：建议排除出知识库，仅保留在 `工作内容/` 备查
4. **xlsx**（11 个：验算、标准答案、重点整理）：结构化数据，阶段 2 后按需处理
