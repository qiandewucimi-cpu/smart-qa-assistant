## 0. 电梯陈述（30 秒版）

> 这是一个企业知识库问答助手。我把一家公司散落的 121 份内部资料（文档、表格、PPT、聊天截图）
> 清洗脱敏后建成知识库，接上大模型做检索问答，并做了完整的自动化评测来证明效果。
> 现在命中率 85%~90%、幻觉 0/21，端到端延迟从 61.5 秒压到 18 秒。
> 我主要负责的是**数据清洗脱敏、评测体系、机器人接入和归因方法论**这四块。

**讲完立刻停。** 等对方追问——追问方向决定了你讲哪一块。

## 1. 边界问题：哪些是你写的，哪些是第三方的（**必背，最大翻车点**）

面试官最可能问：「RAG 是你自己实现的吗？」

**诚实答案：检索层不是我实现的，我用了一个第三方编译式知识库（LLM Wiki）+ 国产大模型 API。**

但**不要停在这里**，要立刻接上「那我做了什么」：

| 层面 | 谁做的 | 具体 |
|---|---|---|
| 向量检索 / 知识库编译 | **第三方应用** | LLM Wiki v0.6.11（编译式知识库，把文档编译成结构化 wiki 页） |
| 大模型 | **第三方 API** | 智谱 GLM |
| **数据清洗 + 脱敏** | **我** | 121 份 → 105.2 万字符；脱敏 **4,667 处**（文本 1,586 + 截图 OCR 3,081）；自研 7 类脱敏规则 |
| **评测体系** | **我** | 33 个脚本 / 5,731 行；22 题主评测集 + 45 题扩展集 + 65 题扩展；自动判定、置信区间、A/B 对照 |
| **问题定位与优化** | **我** | 检索深度 topK 5→15、模型选型实测、术语对照页沉淀、续跑兜底 |
| **机器人接入** | **我** | 飞书自建应用，长连接、卡片消息、多轮会话、退避重试、用量埋点 |
| **归因方法论** | **我** | 单变量对照、置信区间、拒绝无对照的归因（见 §5） |

**为什么选第三方而不是自己写检索器？** 这是加分项，主动讲：
> 目标是**在真实资料上验证效果**，不是造轮子。自己写检索器要花掉大部分时间，
> 而我想把力气放在「怎么证明这个系统真的能用」上——清洗、评测、归因。
> 这套方法论换任何检索器都成立。

**证据**：`docs/需求分析.md`（选型理由）、`docs/复盘报告.md` §4 关键决策。

## 3. 高频追问 Q&A

### Q1「为什么命中率不是 99%？剩下的错在哪？」

答：分两类。**框架性失败**（撞了 agent 的 8 步工具迭代上限，约 12%，集中在 4 道题）
和**零召回后用参数记忆作答**（约 2%~3%，这个更危险——是自信的错答案）。
我后来把主指标从「命中率」换成了「零召回率 / 零召回仍作答率」，
因为前者会漏掉最危险的那类失败。

**证据**：`eval/评测报告_v1.3_扩展集与框架失败成因.md` §8.5。

### Q2「你怎么保证没有幻觉？」

答：三层。① 评测集判「命中/答偏/幻觉」三档，实测 0/21；
② 单独做了**拒答专项**——语料外的题 8/8 正确拒答、语料内冷门题 5/5 无误拒，
这一项是为了防止「幻觉 0」是靠**拒答刷出来的**；
③ 后来发现更隐蔽的形态：检索返回 0 条但模型仍给实体性答案，
这个 `framework_failure` 判不出来，我加了 `param_memory_answer()` 专门抓它。

**证据**：`eval/拒答评测报告.md`、`scripts/eval_common.py`。

### Q3「脱敏怎么做的？真实数据怎么保证不泄漏？」

答：四道闸门。① 输入侧扫清洗后语料；② 输出侧扫评测产物（检索变宽后引用会带回真实实体页，
这条是踩过坑才加的）；③ 提交前扫所有入库文件；④ 机器人**出站前**再擦一遍答案和来源标题。
另外我用 `git filter-repo` 把全部 20 个提交的历史也重写了一遍。
**真实词表不进仓库**，放在本地 gitignore 的文件里。

⚠️ **注意措辞**：只能说「**清洗后语料零残留**」，**不能**说「全项目零残留」——
wiki 编译产物层还有编译期派生的残留，我如实记在复盘报告里了。

**证据**：`docs/复盘报告.md` §3.1、§5 坑 11/12/19。

### Q4「向量检索用了吗？」

答：**配了但没生效**，而且我一开始误以为是它起的作用。
embedding 接口额度耗尽返回 429，应用静默降级，`vectorHits` 恒为 0。
我是复核归因时发现的，然后**公开更正了报告和文档**。
现在配置里 `enabled=false` 以匹配现实，索引保留待充值后一键恢复。

**这是亮点，不是污点**——见 §5。

**证据**：`eval/评测报告_v1.0_检索深度与快模型.md` §6、§7。

### Q5「延迟怎么优化的？」

答：先测再改。写了对照基准脚本，实测 glm-4.5-air P50 12.9s vs glm-4.7 60.1s，
并且**证伪了「关掉思考链能提速」**（关了仍 59.5s）。切模型后端到端 P50 61.5s→18.0s。
后来我又实测确认**更强的模型没有质量收益**（95% vs 95~97%，只慢 4.7 倍），
所以没有为了「看起来更强」去换模型。

**证据**：`scripts/bench_chat_latency.py`、`docs/复盘报告.md` §4.7。

### Q6「遇到最大的技术难点是什么？」

推荐讲这个：**P1 题命中率 0/5**。
根因不是检索不准，是**术语不匹配**——题干说「订单审核通过」，语料里写的是另一个内部叫法。
我没有去改检索器，而是用引擎自带的「查询页」机制沉淀了一张术语对照表，
单变量 A/B 从 **0/5 提到 4/5（Fisher 单侧 p=0.024）**，
且**两个无关题两臂无差异**——这一步很关键，它排除了「只是整体变好了」。

**证据**：`wiki-patches/queries/`、`eval/评测报告_v1.3…md`。

### Q7「你怎么知道改动是有效的？」

答：任何「改了 X 所以 Y 变好」都必须有**对照组**，而且要有**负对照**
（改的东西不该影响的题，必须没变化）。我在这上面栽过两次跟头，
所以后来把它写成了项目硬规矩。

**证据**：见 §5。

### Q8「为什么选飞书？」

答：个人账号就能建企业自建应用，WebSocket 长连接**免公网服务器、发布免审核**；
企微机器人仅限内部群。实测长连接通、卡片消息和多轮会话都跑通了。

**证据**：`docs/机器人接入调研.md`。

### Q9「有没有真实用户用过？」

**答：如实说还在积累。** 埋点链路已经做好（只记元数据、不记问题原文），
但真实用量数据还没有。**不要编「服务了多少人」**——
可以说「采集已就绪，对照实验方案在复盘报告 §6.3」。
诚实比编数字安全得多。

### Q10「如果重做一次你会改什么？」

推荐答：① **一开始就建每题基线和足够样本量**——我前期用 21 题，
只要藏一道「看起来命中、其实 1/10」的题就能造成 ±4.8pp 的假象，我后期才发现；
② **先把评测和归因体系搭好再调参**，我前期反了。

## 4. 你主动要说的短板（**不要等对方挖**）

坦诚说明显比被发现更好。三句话讲完，然后转向「我怎么处理的」：

1. **D1/D2 两道题的表现会在不同轮次间摇摆**（同配置 09-13 两轮 10/10 成功、另一天 5/5 失败）。
   我排查了 5 个假设（模型弱 / 接口慢 / 知识库变了 / 检索失效 / 页面链接诱导）**全部被否掉**，
   根因未找到。我没有硬凑一个解释。
2. **wiki 编译产物层仍有编译期派生的真实专名残留**，需要单独一轮重抽重编，
   那一轮会让现有数字作废，所以我把它和评测解耦、单独排期。
3. **用户价值数字（找资料耗时、服务人数）还没实测**，只有测量方案。

## 5. 两个归因纠错的故事（**最好的亮点素材**）

### 故事 1：我以为功劳是向量检索的，其实它压根没生效

一开始命中率提升，我归因给「开启了向量检索」。复核时发现
**向量全程未生效**（额度耗尽、评测里 0 次向量召回）。
我公开更正了报告、改了文件名、在文档里写清真实归因（检索深度 + 换模型），
还加了一个 `probe` 自检脚本防止以后再犯。

**讲法**：结论错了不可怕，可怕的是结论不可复算。我建立了「改完检索配置必须先自检再谈效果」的规矩。

### 故事 2：我把「D1 命中率低」归因给换模型，但我从没做过模型对照

初稿写「换成快模型后 D1 退化」，补测后发现两个假设都站不住：
引用数恒定 → 不是检索面的问题；**从未做过模型对照** → 不能归因给模型。
真相是：**D1 本就在 8 步上限边缘，那次命中是 1/10 里的那一次，不是退化，是从来没测过基线**。

**讲法**：这是同一个错误犯了两次，之后我把它固化成了硬规矩——
**没对照组就只能写「此前未测过基线」，不许用「退化/变差」这类因果词**。
