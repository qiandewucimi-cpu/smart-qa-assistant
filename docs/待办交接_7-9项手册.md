## 第 7 项 · wiki 侧真实专名清理（**必须单独一轮，不要和其他任务混做**）

### 现状（2026-09-14 实测）

- `python scripts/audit_leaks.py` → **11 个文件共 58 处残留**
- 性质：这些不是输入侧漏网，而是 **LLM 编译期的派生与推断**
  （例：从银行地址里的城市线索推断出「所在国家」——输入里根本没有国家字段；
  真实订单号被编译成实体页 `订单号-<编号>`）
- 目前**仅存在于 gitignore 的 `projects/` 目录**，公开仓库不受影响
- ⚠️ 但转 public 前，以及「知识库真正对外检索的那一层」是这一层，所以必须清

### ⚠️ 为什么必须单独一轮

完整流程会**重抽 `data/clean` → 重编 wiki**，这意味着：

- **前几轮所有评测数字作废**（命中率、零召回率、扩展集……全部要重跑）
- 全量重编 119 份文档，上次耗时数小时
- 如果和别的任务混着做，会出现「数字刚改完就被作废」的返工

**前置条件：第 1~6 项全部收口、且已提交。**

### 执行步骤

| 步 | 动作 | 命令 / 位置 | 验收 |
|---|---|---|---|
| 0 | 备份（**必做**） | `cp -r projects projects.bak`；确认 git 工作区干净 | 备份目录存在 |
| 1 | 导出残留清单 | `python scripts/audit_leaks.py` → 记录 11 个文件路径 | 拿到清单 |
| 2 | **人工判断**每一处是真名还是误报 | 逐条看，注意词边界（别把长词内部的短词当命中） | 得到「真需处理」清单 |
| 3 | 补词表 | 追加到 `scripts/maps_local.py`（**gitignore，不进仓库**） | 词表条目数 +N |
| 4 | 补结构化规则 | `scripts/clean_text.py`（派生形态如订单号、城市→国家推断） | 规则生效 |
| 5 | 重抽清洗语料 | 重跑抽取 → 覆盖 `data/clean/` | `audit_leaks.py --only clean` → 0 |
| 6 | 重导 + 重编 | `scripts/reingest.py` → 全量编译 | `wiki_status.py`：119/119、0 失败 |
| 7 | 复扫 wiki | `python scripts/audit_leaks.py` | 目标 0 处（达不到则回到第 2 步） |
| 8 | **重跑全部评测** | `eval_chat.py` / 扩展集 / 拒答专项 | 得到新一轮数字 |
| 9 | 文档全部回填 | 复盘报告 / 简历素材 / 评测报告 / 进度表 | 四份一致 |

### 风险与回滚

- **风险**：步骤 6 编译中途失败 → 知识库处于半新半旧状态
- **回滚**：第 0 步的 `projects.bak`；`scripts/resume_ingest.py` 支持续跑
- **⚠️ 词表是 gitignore 的**：改之前先 `cp scripts/maps_local.py scripts/maps_local.py.bak`
  （2026-09-14 曾因脚本「解析失败却继续写文件」删掉 18 条真实词，靠编辑器备份才救回）

## 第 8 项 · P2 语料口径向业务确认（**卡在业务侧**）

### 问题

P2 题（核料纸样 / 是否需要制版）在语料里**有两处互相矛盾的说法**，
评测集已把它标为**不计分**，但这只是回避，没有解决。

### 给业务方的提问模板（可直接复制发送）

> 想确认一个流程口径（内部资料里看到两种说法，需要一个准的）：
>
> **问题**：下「核料纸样」单的时候，**是否需要先制版**？
>
> - 说法 A：<资料甲> 里写的是「核料纸样 → 制版 → 大货」
> - 说法 B：<资料乙> 里写的是「核料纸样单不需要制版，可直接进入下一步」
>
> 麻烦确认：
> 1. 哪个是现行口径？（或者：两者适用场景不同？如果是，分别是什么场景？）
> 2. 如果分场景，判断条件是什么？
>
> 背景：这个口径会写进知识库，答错会影响下游，所以想要一个明确说法。

### 拿到答复后

1. 更新 `data/clean/` 里对应的两份语料（把矛盾的其中一份改成明确的条件分支）
2. 把 `eval/评测集.md` 里 P2 的 `scoring: false` 改成 `true`
3. 重跑评测，P2 计入分母后**所有命中率数字会变** → 需要回填文档
