# 评测报告 · v1.1（知识固化 + 稳定性采样）

> 日期：2026-09-12 ｜ 评测集：`eval/评测集.md` v0.2（22 题，21 计分 + P2 不计分）
> 上一版：`eval/评测报告_v1.0_检索深度与快模型.md`（18→19/21，向量未生效）
> 本轮改动：① **新增 1 页人工沉淀的术语对照页**（知识固化，非改检索器）；② **把「单轮命中率」降级为参考值**，新增「多次采样」为主口径
> ⚠️ 本轮最重要的产出不是 P1 被修好，而是**发现 v1.0 报的 90.5% 不可复现**——详见 §6/§7
> ⚠️ **本报告也纠了自己一次（见 §6）**：初稿把 D1 的低命中率写成「退化」并归因给换模型，
> 补测后**两个假设都被排除**（引用数恒定 → 不是检索面；从未做模型对照 → 不能归因给模型）。
> 正确说法是「**此前从未测过 D1 的基线稳定性**」。

---

## 0. 一句话结论

P1（连续四轮稳定未命中）**已修复且归因干净**：单变量 A/B 下命中率 **0/5 → 4/5**（Fisher 精确检验单侧 p = 0.024），
手段是**用引擎自带的 `queries/` 页类型沉淀术语对照**，不是改检索器、不是给评测集放水。

但同一批采样暴露了一个**更严重的问题**：**两轮全量都是 18/21，但未命中的题目构成完全不同**
（r1 = D1/D2/P1，r2 = D1/P3/O2）→ 单轮命中率的方差主要来自框架随机失败，而不是知识缺口。
**v1.0 的 90.5% 因此不能作为可复现指标对外报。**

其中 D1 在 10 次采样里只命中 1 次——但**这不叫「退化」**（v1.0 只测过它 1 次，没有基线可比），
真正的问题是：**21 题的评测集里可以藏着一个「看起来命中、其实 1/10」的题，而单轮数字完全看不出来**。

## 2. P1 根因诊断（四条证据）

**现象**：v1.0 起 P1 复跑 0/3，标准答案明明在库里。

| 证据 | 内容 |
|---|---|
| ① 答案页在哪 | 答案原文就在 `wiki/entities/订单理单.md`（第 17 行）：“订单完成CP确认后，基于上游内部合同号+次款号，为每一个单品款号单独生成核料单” |
| ② `/search` 找得到 | 用「订单理单 CP 确认 生成核料单」问，`订单理单` 排 **第 2** |
| ③ chat 找不到 | 用题干原文问，chat 内部检索召回的 15 条里**没有 `订单理单`**，也没有 `采购核料单生成与可见性控制`；排第 1 的是 `采购核料单状态流转与审核规则`（讲的是核料单**自身**的状态流转） |
| ④ 引用被稀释 | chat 的 19 条引用里有 9 条是 **1-hop 图谱扩展**带进来的低价值实体页（飞书、飞书知识库、`log.md`、版师……），分数标度 10007~10027，与关键词路（74~53）不是一套 |

**结论**：根因是**术语不匹配**——题干说「订单审核通过 / 数据如何流转」，语料说「CP 确认 / 订单理单完成 / 生成核料单」。
关键词检索桥接不了这层同义关系；而 chat 的查询改写又随采样漂移，所以**同一题每次召回的都不一样**
（这也解释了为什么 P1 的失败模式会在「拒答」和「轻度编造」之间摇摆）。

## 3. 修复方案：知识固化（可复现）

新增页面做的事：**只做术语映射与链路串接，不新增业务事实**。

- 一句话答案（CP 确认 → 内部合同号+次款号 → 每个单品款号单独生成核料单）
- 术语对照表：`订单审核通过 / 审核完成 / 订单审完` ↔ `CP 确认 / 订单理单完成`；`数据流转到核料单` ↔ `生成采购核料单`
- 易混淆点：**「订单审核通过」≠「核料单机审通过」**（这正是模型答偏的方向）
- 双链挂到 `[[订单理单]] / [[采购核料单]] / [[内部合同号]] / [[采购核料单生成与可见性控制]]`

**可复现性**：`projects/` 是 gitignored 的，所以页面原文存在仓库 `wiki-patches/queries/`，
任何人 clone 后跑 `python scripts/apply_faq_patch.py` 即可得到同样的知识库（`--check` 可挂 CI）。

## 4. 单变量 A/B（只差一个 wiki 页）

同一时段、同一模型、同一 topK=15，只切换「FAQ 页在不在知识库里」，各跑 5 次：

| 题 | FAQ 关（对照） | FAQ 开（实验） | 判定 |
|---|---|---|---|
| **P1**（目标题） | **0/5**（5 次全答偏：讲的是核料单自身状态流转，或泛化的 DLS 叙述） | **4/5** | ✅ **显著改善** |
| D1（无关题 · 加放 vs 短溢装） | 0/5 | 1/5 | 无差异（预期内：与 FAQ 页无关） |
| D2（无关题 · 待核单 vs 已核单） | 3/5 | 2/5 | 无差异（预期内） |

- **Fisher 精确检验（P1，4/5 vs 0/5）单侧 p = 0.024**（超几何：C(4,4)·C(6,1)/C(10,5) = 6/252）。
- P1 命中率点估计 80%，**95% Wilson 区间 [37.6%, 96.4%]**；对照组 0/5 的 **95% 上界 45.1%**。
- **两个无关题在两臂无差异 → 说明改善确实来自这一页，不是环境波动。** 这是本次归因能站住的关键。

> ⚠️ 诚实标注：5 次是小样本，区间很宽。但它足以支撑「从‘基本答不出’变成‘多数能答对’」这个定性结论。

## 5. 两轮全量复测（FAQ 开）

| 轮次 | 命中 | 未命中构成 |
|---|---|---|
| r1 | **18/21（85.7%）** | D1（框架 8 步上限）、D2（框架 8 步上限）、P1（答偏） |
| r2 | **18/21（85.7%）** | D1（框架 8 步上限）、**P3（原文直吐）**、**O2（答偏）** |

- 18/21 的 95% Wilson 区间：**[65.4%, 95.0%]**。
- **两轮命中率相同，但未命中的题目几乎不重合**（交集只有 D1）。
  → 命中率这个数字的**方差主要来自框架的随机失败**，而不是「哪些知识没有」。
  → 因此**单轮命中率不能作为可复现指标**，v1.0 的 90.5% 属于运气偏好的一次采样。

## 6. ⚠️ 新发现：框架随机失败已取代知识缺口，成为第一大失分来源

两轮全量 + 两臂各 5 次采样 + 首轮 P1 试跑（共 **77 次提问**）里，观察到**两种框架失败模式**：

| 模式 | 表现 | 失败次数 |
|---|---|---|
| A. 8 步工具迭代上限 | `The Agent reached the tool-iteration limit after 8 step(s)`，无答案 | **D1 9/10**、**D2 5/10**、P1 0/10 |
| B. 原文直吐 | 答案为 `I found the following relevant project context:` + 检索片段原文，**没有生成回答** | P3（r2）1/22 |

**D1 最刺眼**：v1.0 时它是命中题，本轮 **10 次采样只成功 1 次（1/10，95% Wilson [1.8%, 40.4%]）**。
D1 问的是「加放系数和短溢装的区别」，与本次新增的 FAQ 页**毫无关系**，且对照臂同样 0/5 —— **不是本轮改动引入的**。

**⚠️ 但不能叫「退化」，而且我一开始的归因是错的**

初稿我把这件事归给了「换 `glm-4.5-air` 让 agent 更容易触顶」——**这个归因没有对照，站不住**。补测后两个候选假设都被排除：

| 候选假设 | 检验 | 结论 |
|---|---|---|
| 检索面变宽导致步数触顶 | 查各轮 D1 的引用数：v0.3（topK 默认）**10 条**、v1.0 命中那次 **10 条**、v1.1 失败 **10 条**、A/B 五次全 **10 条** | ❌ **排除**：引用数恒定，与 topK / FAQ 页都无关 |
| 换 `glm-4.5-air` 导致 | **从未做过模型对照**（v1.0 的 D1 只有 1 次采样，且是换模型之后） | ❌ **不能归因**：没有换回 `glm-4.7` 的对照数据 |

**最可能的解释（也是最朴素的那个）**：D1 本来就一直站在 8 步上限的边缘，
**v1.0 那唯一一次命中，就是这 1/10 里的那一次**。
也就是说——不是它退化了，而是**我们从来没有测过它的基线稳定性，却默认它是稳定的**。

> 教训（这条比 D1 本身值钱）：**没有基线稳定性数据，就不能用「退化」这个词。**
> 「之前是好的、现在坏了」是一个因果断言，需要前后各 N 次采样；只有 1 次采样时，
> 唯一诚实的说法是「**之前不知道它不稳定**」。
> 这也是我在上一份报告里刚立过的规矩（归因要单变量对照），转头就自己犯了——记在这里。

## 7. 口径修正建议（对外怎么报）

| 口径 | v1.0 做法 | v1.1 建议 | 理由 |
|---|---|---|---|
| 命中率 | 单轮 90.5%（19/21） | **报区间 + 复跑次数**：本轮两轮均 18/21（85.7%，95% CI [65.4%, 95.0%]）；并注明框架失败导致的波动 ±1~2 题 | 两轮未命中构成不重合 |
| 幻觉 | 「0/21」 | **保留 0/21，但限定为本次采样**；且模式 B（原文直吐）说明答案正文可能夹带语料原文 | 已有口径，继续收紧 |
| 稳定性 | 只给 P1/D2 复跑 | **新增为独立维度**：D1 命中 1/10、D2 命中 5/10、P1 命中 4/5（当前配置下） | 已量化 |

**不要做的事**：不要因为两轮都是 18/21 就把主口径改成 85.7% 然后对外说"稳定 85.7%"——
两轮不重合恰恰说明它**不稳定**，正确说法是「**18~19/21，随框架随机失败波动**」。

## 9. 复算方式

```bash
# 1) 复现知识库改动
python scripts/apply_faq_patch.py           # 注入 wiki-patches/queries → wiki/queries
python scripts/apply_faq_patch.py --check   # 校验（缺失/不一致退出码 1）

# 2) P1 / D1 / D2 稳定性采样（FAQ 开）
python scripts/eval_chat.py --only D1,D2,P1 --repeat 5 --tag ab_faq_on
#    对照臂：把 wiki/queries/订单审核与采购核料单数据流转.md 临时改名后再跑同上命令

# 3) 全量复测
python scripts/eval_chat.py --tag v1.1_faq

# 4) 提交前必跑（输出侧脱敏）
python scripts/sanitize_eval_results.py --check
```

- 运行日志：`eval/eval_run_v1.1.log`、`eval_run_ab_faq_on.log`、`eval_run_ab_faq_off.log`、`eval_run_v1.1_r2.log`
