# 订单审核通过后数据如何流转到采购核料单

> 人工沉淀的**术语对照 / 高频问答**页。背景：业务同学习惯说「订单审核通过」，
> 而语料与系统里的说法是「CP 确认 / 订单理单完成」，两种说法对不上导致检索答偏。
> 本页只做**术语映射与链路串接**，不新增业务事实。

## 一句话答案

订单完成 **CP 确认** 后，系统基于上游的 **内部合同号 + 次款号**，为**每一个单品款号单独生成**
一张采购核料单；色码明细由上游订单理单自动带入，拆分至单款单色单码，无需手动填写。

## 术语对照（常见说法 ↔ 本知识库术语）

| 常见说法 | 本知识库对应术语 | 说明 |
|---|---|---|
| 订单审核通过 / 审核完成 / 订单审完 | **CP 确认**、**订单理单完成** | 指上游[[订单理单]]流程走完、单据被确认的动作 |
| 数据流转到核料单 | **生成[[采购核料单]]** | 不是"把字段同步过去"，而是按上游数据**生成一张新单据** |
| 单品款号 | 内部合同号下的**次款号** | 一个次款号对应一张核料单 |

## 完整流转链路

1. 上游[[订单理单]]完成 **CP 确认**；
2. 系统取该订单的**内部合同号 + 次款号**；
3. 按**每一个单品款号**分别生成采购核料单；
4. 生成时自动带入内部合同、款式、客户、品类、产地、采购方式、下单主体、CP 树等信息；
5. 色码明细由上游订单理单自动带入，拆分至**单款单色单码**；
6. 若存在历史同款，按翻单逻辑标识并允许引用历史资料。

## 易混淆点

- **「订单审核通过」≠「核料单机审通过」**：前者是上游订单理单的 CP 确认；后者是核料单自身的
  流转状态（见[[采购核料单状态流转与审核规则]]）。两者是不同单据上的不同动作。
- **不是"一张订单对应一张核料单"**：是**一个次款号对应一张**，一张订单下会生成多张核料单。
- **生成 ≠ 可见**：核料单生成后能否看到，还受下单主体 / 业务组 / 单耗部门 / 指定单耗师等权限控制
  （见[[采购核料单生成与可见性控制]]）。
