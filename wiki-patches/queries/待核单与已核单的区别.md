# 待核单与已核单的区别

> 人工沉淀的**对比 / 高频问答**页。这两张单据分属 [[待核单]] 与 [[已核单]] 两页，
> 问「有什么区别」时需要各查一次再比较，容易在应用的**工具步数上限**前失败。
> 本页只把两页内容**并排放置**，不新增任何业务事实。

## 一句话答案

**待核单是系统自动生成的「原始核验单据」，是理单流程的中间状态；
已核单是把待核单按指定条件「合并」之后生成的最终核验单据，并拿到唯一的内部合同号，
成为后续单据流转的核心标识。**

## 并排对照

| 维度 | 待核单 | 已核单 |
|---|---|---|
| **怎么来的** | 系统**自动生成** | 由待核单**按指定条件合并**生成 |
| **生成时机 / 来源** | 意向、正式订单**审核通过后** | 待核单产生之后，合并而成 |
| **生成维度** | 按**制款维度**生成 | 按合并条件归集（同一客户下多个待核单） |
| **数量关系** | 单款订单 1 条数据；套装订单对应**多条**制款数据 | 多条待核单合并为**一条** |
| **数据角色** | 理单流程的**中间状态**，为合并提供基础数据 | **最终单据**，后续流转的**核心标识** |
| **标识** | 关联原始订单号 | 生成唯一的**内部合同号** |

## 链路上的先后关系

1. 意向 / 正式订单**审核通过** → 系统按制款维度自动生成**待核单**；
2. 按合并条件（见[[核单合并规则]]）把待核单**合并** → 生成**已核单**；
3. 已核单拿到**内部合同号**，往后贯穿采购、生产等环节。

> 一句话记法：**待核单是「合并前」，已核单是「合并后 + 有了内部合同号」。**

## 待核单自带的字段（供区分用）

| 字段 | 说明 |
|---|---|
| 订单号 | 关联原始订单的唯一标识 |
| 制款信息 / 客款信息 | 款式与客户相关的基础信息 |
| 数量 | 订单数量 |
| 包装方式对应成品件数 | 按包装方式算出的成品件数 |
| 最早 / 最晚出厂日期 | 全批次中的最早、最晚出厂日期 |

## 易混淆点

- **「待核单」的「待」不是「等待审核」**：它是**订单审核通过之后**才自动生成的，
  指的是「等待被合并/核验」，**不是**「还没审核」。
- **不是「一张订单一张已核单」**：是以**合并条件**归集的，同一客户下多个待核单可合并为一张。
- 合并的具体条件（客系列 / 自系列 / 客季节+客系列 / 客季节+自系列 / 手动核单）见[[核单合并规则]]。
